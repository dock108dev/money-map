# Safe local financial-data update

Updated October 7, 2026. Scope: personal use and a handful of users. [Working approach](../personal-use.md).

For actual owner-data setup or migration, use the existing supported selection/import/DataHomeManager route and its real backup/confirmation controls. This plan does not authorize reading financial files or Keychain data.

1. Select the intended source/data root explicitly.
2. Take a complete supported backup. Use a copy when a migration is destructive or unfamiliar.
3. Follow the existing app's preview/confirmation and schema compatibility checks; do not hand-edit journals, data or accounting.
4. Apply the needed update, open the app and check affected account totals, saved plans and return/reopen.
5. Keep the original and backup so a failed update can be restored.

A new signed package, installed qualification campaign or formal beta verdict is not a data-setup prerequisite. Keep current implementation guards; simplifying documentation does not bypass them. Do not infer newer schema support from this guide—use the running app's actual compatibility checks.
